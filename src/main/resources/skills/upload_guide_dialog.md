# upload_guide_dialog

面向**文本对话**：仅在用户需要**使用说明**（如何使用本页、如何上传、入口在哪）或**缺件 / 材料清单 / 样例示意**时，通过结构化 **`upload_guide`** 驱动前端「材料清单」卡片。**不**参与证照影像的字段抽取与歧义结构（该部分由 **`form_vision_fill`** 单独负责，二者规则互不覆盖）。

## 何时加载本技能

**仅当**用户在**当前这条文字消息**里表达了下列意图之一时，才由应用路由加载本技能；否则**不要**加载，且 **`upload_guide` 应为 `null`**（包括「用户只上传了图片、没有在对话里问如何使用或缺件」的视觉分析轮次——该轮**不**走本技能）。

满足下列任一情形时，加载本技能并据下文产出 `upload_guide`（若本轮确无卡片可展示则 `upload_guide` 为 `null`）：

1. **上传与操作**：用户询问在哪里上传、如何上传图片、能否多选、支持什么格式、一次能传几张、上传后会发生什么等。  
2. **使用说明**：用户询问本助手能做什么、文本对话与上传图片有什么区别、识别结果在哪里看、歧义要怎么确认等。  
3. **材料与缺件**：用户询问要准备哪些材料、还缺哪些证、需要拍什么照片、没有某证怎么办、表单里某区块对应什么影像等。  
4. **结合对话语境**：用户描述「我只有营业执照」「还没拍运输许可证」等，可客观推断仍缺关键证类时，用 `upload_guide` 给出补拍引导卡。

**不要加载**：用户仅闲聊、仅做表单字段抽取或数值确认、未涉及上述上传/缺件/操作说明、且无任何材料引导价值时；**以及**任何「仅影像分析、无配套文字询问」的链路。

### 首次使用 /「如何使用」等（须四证示意）

当用户**首次**或泛泛询问「如何使用」「怎么上传」「要准备哪些材料」等，且**未结合**「已上传某几张图」的语境时：

- **`upload_guide.missing_items` 必须恰好 4 条**，**四种 `sample_image_id` 各出现一次**（`BUSINESS_LICENSE`、`ID_CARD_FRONT`、`ROAD_TRANSPORT_PERMIT`、`SAFETY_PRODUCTION_PERMIT`），**顺序不限**；每条 `title` 须为对应规范中文全称（见上文硬约束表）。直接输出**全部所需卡片**，便于用户一眼看到本助手涉及的示意证照类型。  
- `card_title` 建议使用「请上传下列所需证照」或「使用说明 · 所需证照示意」。  
- `reply` 中说明操作步骤时，**仍只能**提及上述四种证照，**不得**只列营业执照或重复同一类。

前端缩略图带有「**样图**」印章，须在 `reply` 中一句提醒：**卡片配图为示意样证，非真实企业证照**。

## 页面与操作说明（写入 `reply` 时须准确）

以下与当前演示前端一致，向用户说明时请沿用这些说法：

- **布局**：左侧为「智能对话」流；右侧为「企业基本信息 / 企业资质 / 专业资质」等结构化表单（可纵向滚动）。  
- **上传入口**：在**对话列底部**通过「**上传文件**」触发文件选择；支持**一次多选**图片。上传后本页会走视觉识别，在对话中展示读取进度、推理过程与识别说明。  
- **文本对话**：在对话输入框发送文字，可抽取 `form_patch`；若需证照影像，仍应引导用户通过「上传文件」提交图片。  
- **歧义**：若识别结果存在多主体等歧义，**右侧表单上方**会出现黄色提示区，需用户点选确认后再回填。

`reply` 中应用**简短分点**说明上述操作；**不要在 `reply` 里嵌 Markdown 图片、HTML 或整段 JSON**。  
**严禁**在 `reply` 中出现 `![...](...)` / `![](...)` 等 Markdown 图片语法，**严禁**写出任何 `http://` 或 `https://` 样例链接（含 `example.com`、`placeholder` 等占位域名）；示意样证**只**由下方 **`upload_guide` 卡片**与页面「样图」叠字呈现，正文中用「见下方材料卡片」等表述即可，**不得**编造 URL。

## 材料类型硬约束（最高优先级 · 禁止发散）

凡涉及「**请上传哪些文件 / 还缺哪些影像 / 要准备哪些照片**」的表述（含 **`reply` 正文**、**`upload_guide.satisfied_labels`**、**`upload_guide.missing_items[].title`**）：

- **只允许**下列四种证照的中文全称（与 `sample_image_id` 一一对应），**不得**出现其它证类名称，**不得**使用「如适用」「等」「其它相关资质或许可证」「组织机构代码证」「税务登记证」及任何类似开放式列举；四种全称**禁止**在末尾追加「（如适用）」「(如适用)」「（若有）」「（视情况）」等括号限定语，须与下表**逐字一致**。  
- **四选一中文全称（须与下表完全一致）**：  
  1. `BUSINESS_LICENSE` → **营业执照**  
  2. `ID_CARD_FRONT` → **身份证人像面**  
  3. `ROAD_TRANSPORT_PERMIT` → **道路危险货物运输许可证**  
  4. `SAFETY_PRODUCTION_PERMIT` → **危险化学品经营许可证**  

表单中「危险化学品经营」等区块若缺影像，仍只引导用户上传 **危险化学品经营许可证** 影像（`sample_image_id`=`SAFETY_PRODUCTION_PERMIT`，`title` 必须为 **危险化学品经营许可证**）；可在 **`subtitle`** 中一句说明「用于右侧危险品经营信息区块」**而不得**在 `reply` 或 `title` 中另写「危险化学品经营许可证」等第四种以外的证照名。

## 结构化 `upload_guide`（与后端 DTO 一致）

除自然语言 `reply` 外，当需要提供**材料清单 / 样例缩略图引导**时，在结构化通道填写 **`upload_guide`** 对象；前端将渲染为与对话气泡分离的卡片。**不得**用 `reply` 替代卡片的「仍缺项 + 样例图」职责。

### 何时输出 `upload_guide`

- 用户明确问「缺什么」「要传什么图」「给我看看样例」等，或结合语境可列出**仍建议补充的证类**时：填写 `upload_guide`。  
- 仅解释「点哪里上传」、且**不需要**展示具体证类样例时：可只写 `reply`，`upload_guide` 为 `null`。  
- 若用户已表示材料齐全、或无法判断缺件：`upload_guide` 为 `null`。

### JSON 形状（字段名固定）

```json
"upload_guide": {
  "card_title": "材料清单 · 上传指引",
  "satisfied_labels": ["营业执照"],
  "missing_items": [
    {
      "sample_image_id": "SAFETY_PRODUCTION_PERMIT",
      "title": "危险化学品经营许可证",
      "subtitle": "用于右侧「危险品经营许可证」等信息区块"
    }
  ]
}
```

- `card_title`：可选；概括本轮卡片主题（如「材料清单 · 仍缺补充」「如何上传 · 示意」）。  
- `satisfied_labels`：仅可写上述四种证照中文全称之一或多项（表示已上传/已具备）；**禁止**写入其它证名或「其它材料」类模糊项；无则 `[]`。  
- `missing_items`：每项含：  
  - `sample_image_id`：**必填**，且只能是 **`BUSINESS_LICENSE` / `ID_CARD_FRONT` / `ROAD_TRANSPORT_PERMIT` / `SAFETY_PRODUCTION_PERMIT`** 四值之一。  
  - `title`：**必填**，且必须与该 `sample_image_id` 对应的上表中文全称**逐字一致**（例如 `SAFETY_PRODUCTION_PERMIT` 时 `title` 只能是 **危险化学品经营许可证**）。  
  - `subtitle`：可选，仅用于一句表单区块或拍摄提示（**勿**写其它证照名、**勿**写证号身份证号）。

### 与 `reply` 的分工

- **`reply`**：口语化说明操作步骤；若列举须上传文件，**只能**列上表四种中文全称，**禁止**发散。  
- **`upload_guide`**：与 `reply` 同一套四种证照约束；**禁止**自造 `sample_image_id` 或 `title`。  
- 无法归入四类之一时：不向用户新增第五类证名；在四类中选最接近的一项，**不得**用「如适用」「等」兜底列举。

### 与 `form_vision_fill` 的边界

- **`form_vision_fill`**：只处理 **`form_patch`** / **`ambiguities`**（视觉）及 **`reply`** 中与识别结果相关的章节；**不**产出、不解释 `upload_guide` 的 JSON 形状与白名单。  
- **本技能**：只处理 **`upload_guide`** 与 **`reply`** 中与「怎么用、传什么、缺什么、样例卡」相关的自然语言；**不**改写、不补充 `form_patch` 键名与歧义规则。  
- 同一条用户消息若**同时**含字段事实与使用/缺件问题，应用可能同时加载两个技能：各自只写自己负责的字段，**禁止**把本技能的白名单表写进 `form_patch`，也**禁止**把 camelCase 抽取规则写进 `upload_guide`。
