# upload_guide_dialog

面向**文本对话**：仅在用户需要**使用说明**（如何使用本页、如何上传、入口在哪）或**缺件 / 材料清单 / 样例示意**时，通过结构化 **`upload_guide`** 驱动前端「材料清单」卡片。**不**参与证照影像的字段抽取与歧义结构（该部分由 **`form_vision_fill`** 单独负责，二者规则互不覆盖）。

## 何时加载本技能

**仅当**用户在**当前这条文字消息**里表达了下列意图之一时，才由应用路由加载本技能；否则**不要**加载，且 **`upload_guide` 应为 `null`**（包括「用户只上传了图片、没有在对话里问如何使用或缺件」的视觉分析轮次——该轮**不**走本技能）。

满足下列任一情形时，加载本技能并据下文产出 `upload_guide`（若本轮确无卡片可展示则 `upload_guide` 为 `null`，**但**下文「泛询问不知道如何使用」小节命中时**例外**，该情形下**禁止** `null`）：

1. **上传与操作**：用户询问在哪里上传、如何上传图片、能否多选、支持什么格式、一次能传几张、上传后会发生什么等。  
2. **使用说明**：用户询问本助手能做什么、文本对话与上传图片有什么区别、识别结果在哪里看、歧义要怎么确认等。  
3. **材料与缺件**：用户询问要准备哪些材料、还缺哪些证、需要拍什么照片、没有某证怎么办、表单里某区块对应什么影像等。  
4. **结合对话语境**：用户描述「我只有营业执照」「还没拍运输许可证」等，可客观推断仍缺关键证类时，用 `upload_guide` 给出补拍引导卡。

**不要加载**：用户仅闲聊、仅做表单字段抽取或数值确认、未涉及上述上传/缺件/操作说明、且无任何材料引导价值时；**以及**任何「仅影像分析、无配套文字询问」的链路。

### 泛询问「不知道如何使用」——**必须稳定四证样例图卡片**（最高优先级）

当用户表达**不知道如何使用、不会操作、或询问上传/材料/文件**等意图时（**命中即生效**，与是否「首次」、是否已上传其它图**无关**；只要**当前文字消息**在问这类问题，就适用本小节，**禁止**用「可只写 reply」跳过卡片）：

**触发示例（非穷举，同义改写也算）**  
「如何使用」「怎么用」「不会用」「怎么上传」「如何上传」「在哪上传」「上传入口」「需要什么文件」「要准备哪些材料」「要传什么图」「材料清单」「样例」「示例图」「示意图」「要拍什么」「须上传哪些」等——凡可被合理理解为**操作说明 / 上传引导 / 材料或样例总览**的，一律视为命中。

**强制输出（稳定性硬约束）**

1. **`upload_guide` 禁止为 `null`**；必须输出材料卡片。  
2. **`upload_guide.missing_items` 必须恰好 4 条**，且 **`sample_image_id` 恰好为下列四个值各出现一次**（**禁止**缺条、重复、替换为其它 id、或与 `title` 错位）：  
   - 第 1 条：`BUSINESS_LICENSE` → `title`：**营业执照**  
   - 第 2 条：`ID_CARD_FRONT` → `title`：**身份证人像面**  
   - 第 3 条：`ROAD_TRANSPORT_PERMIT` → `title`：**道路危险货物运输许可证**  
   - 第 4 条：`SAFETY_PRODUCTION_PERMIT` → `title`：**危险化学品经营许可证**  
   **顺序固定为上述 1→2→3→4**，保证前端与用户每次看到的四证示意**版式与阅读顺序一致**（稳定输出）。  
3. **`satisfied_labels`**：命中本小节时一般为 `[]`。**`missing_items` 必须始终恰好 4 条、顺序固定如第 2 点**；即使用户声称已上传部分证照，**仍输出四条样例行**（四宫格示意不缩水），进度差异仅用 `reply` 口语补充即可。  
4. `card_title` 建议使用「使用说明 · 四证样例示意」或「请上传下列所需证照（示意）」。  
5. `reply` 中说明操作步骤时，**仍只能**提及上述四种证照中文全称，**不得**只列其一或发散到表外证类；并须有一句：**卡片配图为示意样证，非真实企业证照**（与前端「样图」叠字一致）。  
6. **禁止「只写长 `reply`、不给出完整 `upload_guide`」**：命中本小节时，**同一轮输出**必须**同时**包含（1）合规 `reply`、（2）非 `null` 且 `missing_items` **恰好 4 个元素的 JSON 数组**（每个元素对应一条证照样例行）。**禁止**仅输出文字步骤让用户以为已完成引导；**禁止** `missing_items` 只含 1 条或把四种证合并在一条描述里——否则前端「需上传的证件」区只会出现**一张**缩略图，属于**错误交付**。  
7. **`reply` 列举四证时的禁用语（与证照名同一自然段或紧邻列举时一律禁止）**：「如果适用」「如适用」「若有」「视情况」「可选」「按需」「等」「等相关」「及其他证件」及任何弱化四类齐备含义的括注。**四证在正文中须平铺直列四种全称**，与 `upload_guide` 四条一一对应，不得对后两类加条件从句。  
8. **上传入口用语**：在 `reply` 中指引操作时，入口名称须与下文「页面与操作说明」一致，使用「**对话列底部**的 **上传文件**」；**禁止**臆造「页面上的上传按钮」等与当前演示 UI 不符的说法，以免用户找不到入口。

> **与下文「可 `upload_guide` 为 null」的关系**：凡命中本小节触发语，**不适用**「仅解释点哪里上传则可 null」的豁免；**必须先满足本小节**，再写 `reply`。

### 「还缺哪些文件」+ 本会话上传文件名累计（应用注入 · 与泛询问四证**择一**）

当系统提示中出现 **「【本会话材料覆盖推断】」** 段落时（表示用户正在追问仍缺哪些材料，且应用已根据**历次「上传文件」的文件名关键词**累计推断哪些证照类型**可能已出现**）：

1. **不适用**上文「泛询问」小节中「`missing_items` 必须恰好 4 条」的强制。  
2. `satisfied_labels` **仅**列提示中「已推断出现」的四种证照中文全称子集（无则 `[]`）；`missing_items` **仅**列「尚未推断出现」的项（可为 1～3 条；`sample_image_id` 与 `title` 仍须白名单一致）。  
3. 若提示写明四类均已推断出现：`upload_guide` **必须为 `null`**，`reply` 说明无需再补传示意卡。  
4. **禁止**在 `reply` 中编造与提示不一致的「已上传/未上传」结论；若用户文件名无法识别，提示会写「尚无」，此时应引导用户**使用含证照关键词的文件名**重新上传或继续上传仍缺项。

### 首次使用 / 泛泛材料总览（与上节一致时并表）

当用户**首次**或泛泛询问材料总览，且语义已落入上节时，**同样**遵守上节「固定顺序四条 `missing_items`」；若与上节不重叠的其它「缺件」语境，仍遵守后文「材料类型硬约束」与白名单，但**不**要求凑满四条——**唯独**「不知道如何使用 / 上传 / 要什么文件」类泛问**必须**四证示意。

## 页面与操作说明（写入 `reply` 时须准确）

以下与当前演示前端一致，向用户说明时请沿用这些说法：

- **布局**：左侧为「智能对话」流；右侧为「企业基本信息 / 企业资质 / 专业资质」等结构化表单（可纵向滚动）。  
- **上传入口**：在**对话列底部**通过「**上传文件**」触发文件选择；支持**一次多选**图片。上传后本页会走视觉识别，在对话中展示读取进度、推理过程与识别说明。  
- **文本对话**：在对话输入框发送文字，可抽取 `form_patch`；若需证照影像，仍应引导用户通过「上传文件」提交图片。  
- **歧义**：若识别结果存在多主体等歧义，**右侧表单上方**会出现黄色提示区，需用户点选确认后再回填。

`reply` 中应用**简短分点**说明上述操作；**不要在 `reply` 里嵌 Markdown 图片、HTML 或整段 JSON**。  
**严禁**在 `reply` 中出现 `![...](...)` / `![](...)` 等 Markdown 图片语法，**严禁**写出任何 `http://` 或 `https://` 样例链接（含 `example.com`、`placeholder` 等占位域名）；示意样证**只**由下方 **`upload_guide` 卡片**与页面「样图」叠字呈现，正文中用「见下方材料卡片」等表述即可，**不得**编造 URL。

## 材料类型硬约束（最高优先级 · 禁止发散）

凡涉及「**请上传哪些文件 / 还缺哪些影像 / 要准备哪些照片**」的表述（含 **`reply` 正文**、**`upload_guide.satisfied_labels`**、**`upload_guide.missing_items[].title`**）：

- **只允许**下列四种证照的中文全称（与 `sample_image_id` 一一对应），**不得**出现其它证类名称，**不得**使用「如适用」「等」「其它相关资质或许可证」「组织机构代码证」「税务登记证」及任何类似开放式列举；四种全称**禁止**在前后或括号内追加「（如适用）」「(如适用)」「如果适用」「若有」「视情况」「（可选）」等限定语，须与下表**逐字一致**。**命中泛询问四证小节时**，四种全称在 `reply` 中须**无条件并列出现**（不得写成「前两种固定 + 后两种视情况」）。  
- **四种证照中文全称（须与下表完全一致）**：  
  1. `BUSINESS_LICENSE` → **营业执照**  
  2. `ID_CARD_FRONT` → **身份证人像面**  
  3. `ROAD_TRANSPORT_PERMIT` → **道路危险货物运输许可证**  
  4. `SAFETY_PRODUCTION_PERMIT` → **危险化学品经营许可证**  

表单中「危险化学品经营」等区块若缺影像，仍只引导用户上传 **危险化学品经营许可证** 影像（`sample_image_id`=`SAFETY_PRODUCTION_PERMIT`，`title` 必须为 **危险化学品经营许可证**）；可在 **`subtitle`** 中一句说明「用于右侧危险品经营信息区块」**而不得**在 `reply` 或 `title` 中另写「危险化学品经营许可证」等第四种以外的证照名。

## 结构化 `upload_guide`（与后端 DTO 一致）

除自然语言 `reply` 外，当需要提供**材料清单 / 样例缩略图引导**时，在结构化通道填写 **`upload_guide`** 对象；前端将渲染为与对话气泡分离的卡片。**不得**用 `reply` 替代卡片的「仍缺项 + 样例图」职责。  
**特别**：命中「泛询问不知道如何使用」时，**四张样例缩略图完全依赖** `upload_guide.missing_items` **的四个数组元素**渲染；少一条即少一图，故**必须四条齐全**。

### 何时输出 `upload_guide`

- **优先判定 A（泛询问）**：若命中「泛询问不知道如何使用」小节（如何使用 / 怎么上传 / 要什么材料总览等），且**未**出现系统提示「【本会话材料覆盖推断】」：**必须**输出 `upload_guide`，且 **`missing_items` 恰好 4 条、顺序固定为** `BUSINESS_LICENSE` → `ID_CARD_FRONT` → `ROAD_TRANSPORT_PERMIT` → `SAFETY_PRODUCTION_PERMIT`，**禁止** `null`。  
- **优先判定 B（仍缺追问 + 会话覆盖）**：若系统提示含「【本会话材料覆盖推断】」：按该段与上文「还缺哪些文件 + 本会话上传文件名累计」小节填写 `satisfied_labels` / `missing_items`（条数按仍未推断出现的项）；四类均已推断出现则 **`upload_guide` 为 `null`**。  
- 用户明确问「缺什么」「要传什么图」「给我看看样例」等（且**不**属于上条泛询问四证强制时），或结合语境可列出**仍建议补充的证类**时：填写 `upload_guide`（条数按语境，仍须遵守白名单与 `title` 一致）。  
- 仅当用户**只**追问与材料无关的界面细节（例如单句「表单区域能不能缩放」）且**未**出现上传/材料/样例/文件类用语时：可只写 `reply`，`upload_guide` 为 `null`。**不得**将「如何使用」「怎么上传」「需要什么文件」及同义说法归入本条豁免。  
- 若用户已表示材料齐全、或无法判断缺件（且不触发泛询问四证）：`upload_guide` 为 `null`。

### JSON 形状（字段名固定）

**泛询问四证示意（稳定模板，须按需复制 `subtitle` 或留空）**：

```json
"upload_guide": {
  "card_title": "使用说明 · 四证样例示意",
  "satisfied_labels": [],
  "missing_items": [
    { "sample_image_id": "BUSINESS_LICENSE", "title": "营业执照", "subtitle": "示意样图" },
    { "sample_image_id": "ID_CARD_FRONT", "title": "身份证人像面", "subtitle": "示意样图" },
    { "sample_image_id": "ROAD_TRANSPORT_PERMIT", "title": "道路危险货物运输许可证", "subtitle": "示意样图" },
    { "sample_image_id": "SAFETY_PRODUCTION_PERMIT", "title": "危险化学品经营许可证", "subtitle": "示意样图" }
  ]
}
```

**仍缺单证等业务场景示例**（条数可少于 4，**不得**用于「如何使用 / 怎么上传 / 需要什么文件」类泛问）：

```json
"upload_guide": {
  "card_title": "材料清单 · 上传指引",
  "satisfied_labels": ["营业执照"],
  "missing_items": [
    {
      "sample_image_id": "SAFETY_PRODUCTION_PERMIT",
      "title": "危险化学品经营许可证",
      "subtitle": "用于右侧「危险品经营许可证」等信息区块"
    }
  ]
}
```

- `card_title`：可选；概括本轮卡片主题（如「材料清单 · 仍缺补充」「如何上传 · 示意」）。  
- `satisfied_labels`：仅可写上述四种证照中文全称之一或多项（表示已上传/已具备）；**禁止**写入其它证名或「其它材料」类模糊项；无则 `[]`。  
- `missing_items`：每项含：  
  - `sample_image_id`：**必填**，且只能是 **`BUSINESS_LICENSE` / `ID_CARD_FRONT` / `ROAD_TRANSPORT_PERMIT` / `SAFETY_PRODUCTION_PERMIT`** 四值之一。  
  - `title`：**必填**，且必须与该 `sample_image_id` 对应的上表中文全称**逐字一致**（例如 `SAFETY_PRODUCTION_PERMIT` 时 `title` 只能是 **危险化学品经营许可证**）。  
  - `subtitle`：可选，仅用于一句表单区块或拍摄提示（**勿**写其它证照名、**勿**写证号身份证号）。

### 与 `reply` 的分工

- **`reply`**：口语化说明操作步骤；若列举须上传文件，**只能**列上表四种中文全称，**禁止**发散；**禁止**出现上文「禁用语」弱化四证齐备。  
- **`upload_guide`**：与 `reply` 同一套四种证照约束；**禁止**自造 `sample_image_id` 或 `title`。  
- **泛询问四证命中时**：`reply` 与 `upload_guide` **缺一不可**；仅 `reply` 无结构化四卡 = **未完成**。  
- 无法归入四类之一时：不向用户新增第五类证名；在四类中选最接近的一项，**不得**用「如适用」「等」兜底列举。

### 与 `form_vision_fill` 的边界

- **`form_vision_fill`**：只处理 **`form_patch`** / **`ambiguities`**（视觉）及 **`reply`** 中与识别结果相关的章节；**不**产出、不解释 `upload_guide` 的 JSON 形状与白名单。  
- **本技能**：只处理 **`upload_guide`** 与 **`reply`** 中与「怎么用、传什么、缺什么、样例卡」相关的自然语言；**不**改写、不补充 `form_patch` 键名与歧义规则。  
- 同一条用户消息若**同时**含字段事实与使用/缺件问题，应用可能同时加载两个技能：各自只写自己负责的字段，**禁止**把本技能的白名单表写进 `form_patch`，也**禁止**把 camelCase 抽取规则写进 `upload_guide`。
